# CLOUD MODE｜2026-09-16 → 2026-09-20

**Project:** 中国古建筑3D复原（ARCH3D-001）  
**Rule ID:** RC-014  
**Status:** APPROVED / PLANNED TEMPORARY OPERATING MODE  
**Expected active window:** 2026-09-16 through 2026-09-20  
**Scope:** 仅《中国古建筑3D复原》项目，不适用于《诡舍·黑衣夫人》或其他项目。

## 1. 目的

在 Product Owner 暂时无法使用本地 MacBook 的期间，允许项目继续推进可由 ChatGPT App、Codex Cloud 与 GitHub 完成的工作，同时保护既有本地 Blender、二进制资产与验收基线，避免因执行环境变化造成伪验收、状态漂移或返工。

本规则是**临时运行环境覆盖层**，不修改 P3 的技术目标、DoD、Hard Fail、Evidence Boundary、Gate 审批权或既有 Governance。

## 2. 工具职责

### ChatGPT App

负责：

- 每次开工先读取 GitHub `main` 上最新 Project Control、相关 Task Contract、提交与 PR；
- 项目分析、方案设计、Task Contract、Hard Fail / Evidence Boundary 判断；
- Codex Cloud 结果审核；
- Gate / Task 状态判断；
- 经 Product Owner 授权后直接维护 GitHub Project Control。

### Codex Cloud

负责：

- 仅基于 GitHub 已存在且可访问的仓库内容执行工程任务；
- 代码、JSON、Registry、Schema、验证器、自动测试、文档与其他确定性仓库内工作；
- 按 Task Contract 自测并返回 diff / commit / PR 与验证结果；
- 遇到合同外证据冲突、资产缺失、执行环境能力不足或需要本地 Mac/Blender 的工作时 STOP 并报告，不得自行降低标准。

### GitHub Web / App

作为：

- canonical committed state；
- 唯一跨设备事实源；
- branch / PR / commit / review / rollback 层；
- Project Control 与 Cloud 产物的正式版本记录。

### Local Mac

在 Cloud Mode 激活期间视为：

`TEMPORARILY UNAVAILABLE`

不得假定可访问本地 working copy、`.blend`、本地 Blender executable、未提交图片/音频/视频、FFmpeg 输出或其他 local-only 资产。

## 3. Cloud Mode 开工规则

每次新工作会话必须：

1. 从 GitHub `main` 读取最新 `docs/project_control/`；
2. 核对最新 Task / Gate / blocker / next_action；
3. 核对相关 PR、branch 与最新提交；
4. 不以聊天记忆替代 GitHub 当前事实；
5. GitHub 与聊天历史不一致时，以 GitHub canonical committed state 为准。

## 4. 任务分类

### A｜可正常推进

允许正式执行并按既有标准验收：

- Markdown / Project Control / Task Contract；
- JSON / Schema / Registry；
- Python / JavaScript 等仓库内脚本；
- validator / automated tests / static checks；
- 证据映射、关系定义、参数规则、数据转换；
- 不依赖 local-only binary 的工程分析与文档；
- GitHub 内可完整复现、验证和审查的其他工作。

### B｜可完成设计，但执行或最终验收延期

包括：

- 依赖本地 Blender 的几何生成设计；
- 需要本地正式 `.blend` 的实现方案；
- 需要 Product Owner 在本地查看正式渲染或交互场景的视觉判断；
- 其他可以完成 Task Contract / 参数 / 算法设计，但缺少正式执行环境的工作。

状态统一采用：

`DESIGN COMPLETE / LOCAL EXECUTION OR REVIEW PENDING`

不得因为设计完成而宣称工程 PASS。

### C｜必须延期

包括：

- 访问 local-only `.blend`；
- 调用 `/Applications/Blender.app/...` 本地 Blender；
- 本地 GUI / CLI Blender 正式生产；
- 本地独立 reopen / render / mutation 验证；
- 访问未进入 GitHub 的二进制资产；
- 任何明确要求 Mac 本地环境的正式验收。

状态统一采用：

`DEFERRED / LOCAL_MAC_REQUIRED`

该状态属于 **temporary execution constraint**，默认不登记为项目技术 blocker，除非它实际阻止当前 Gate 继续产生任何有价值进展。

## 5. Cloud 工程分支规则

Cloud Mode 默认采用：

`ONE TASK = ONE BRANCH = ONE PR`

规则：

1. Codex Cloud 从当时最新 `main` 开始；
2. 每个独立 T-### 使用独立 branch / PR，除非任务本身只是 Product Control 的轻量直接维护；
3. PR 必须包含任务范围、验证结果和已知限制；
4. ChatGPT 完成工程/结构审核后，Product Owner 仍保留正式 Gate Approval；
5. 未通过审核的 Cloud 产物不得通过“看起来完成”直接升级为 PASS；
6. 不在多个 Cloud branch 中并行修改同一 Project Control 文件；
7. merge 后再把下一 Current Task 建立在最新 `main` 上。

## 6. Blender 与视觉验收边界

- 当前本地 Blender 3.6.23 / Intel x64 基线继续有效，但 Cloud Mode 不假定 Codex Cloud 具备等价 Blender 环境；
- 未经独立 Task Contract 验证，不把 Cloud Blender 视为正式生产节点；
- 需要本地 Blender executable、`.blend` 二进制、独立 reopen、正式 render 或本地视觉确认的 DoD 项不得在 Cloud Mode 中虚假勾选 PASS；
- Cloud 可生成设计、脚本和待执行输入，但必须清楚标记 local execution / review pending。

## 7. Project Control 规则

Cloud Mode 期间继续遵守：

- `GitHub main = canonical committed state`；
- `Project Control = SSOT`；
- Dashboard 仍为派生可视化，不提升为事实源；
- 重大决策、Task 状态、Gate 状态、Governance 变化即时落档；
- 每日正式收尾继续执行 `DAILY_PROJECT_CONTROL_CONSISTENCY_AUDIT`；
- 不因为无法访问本地 Mac 而修改历史验收结论或降低 DoD。

## 8. 当前 P3.2 特别约束

Cloud Mode 不改变当前 P3.2 的任何已锁定规则，包括但不限于：

- P3.1 evidence / component identity boundary；
- `REFERENCE_LENGTH_LEAKS_INTO_ASSEMBLY` Hard Fail；
- 六椽栿 1000 mm canonical reference 不得泄漏为建筑实际长度；
- Proxy / Control / Envelope / Deferred / UNKNOWN 不得静默历史化；
- P3.3 在 P3.2 PASS 前继续 LOCKED。

若 P3.2 某项 DoD 必须依赖本地 Blender 或本地视觉确认，则只允许推进到其真实可验证状态，不得因 Cloud Mode 降级 Gate 标准。

## 9. 返回本地后的恢复流程

恢复使用 Mac 后，第一次本地开工必须：

1. `git-proxy-auto pull --ff-only origin main`；
2. 核对 Cloud Mode 期间所有已 merge PR / commit；
3. 核对 Project Control 与本地 working copy 一致；
4. 汇总所有 `LOCAL_EXECUTION OR REVIEW PENDING` 与 `DEFERRED / LOCAL_MAC_REQUIRED` 项；
5. 按优先级补做本地 Blender / binary / visual validation；
6. 不重新执行已经在 Cloud 中具备完整证据并正式 PASS 的纯仓库任务；
7. 完成一次 Project Control consistency audit 后恢复正常 Local + Cloud 混合工作模式。

## 10. 生效与调整

- 本规则于 2026-09-14 经 Product Owner 明确批准建立；
- 预计 2026-09-16 开始实际使用，2026-09-20 结束；
- 2026-09-15 若继续进行本地 Mac 工作，应在当天依据最新项目状态更新进入 Cloud Mode 前的最终 snapshot / pending list；
- Product Owner 可提前结束、延长或修改本规则；
- Cloud Mode 结束后 RC-014 保留为历史记录，不自动转为长期默认 Governance。
