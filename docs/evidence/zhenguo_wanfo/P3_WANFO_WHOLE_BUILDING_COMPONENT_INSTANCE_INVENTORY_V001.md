# 万佛殿整殿构件实例总表 V001｜阶段落档

**日期：** 2026-09-19  
**项目：** ARCH3D-001｜中国古建筑3D复原  
**对象：** 平遥镇国寺万佛殿  
**状态：** 第一轮已归档 / 尚未达到整殿最终完整清单  
**事实源：** SRC-ZG-WF-001《山西平遥镇国寺万佛殿与天王殿精细测绘报告》

## 1. 本轮目的

此前项目已经建立 11 类工程 family、40 个 variant、365 个工程 instance，但本轮重新核读精细测绘报告后确认：

> 11/40/365 是现有工程骨架与控制对象体系，不等于万佛殿真实建筑构件的最终实例清单。

本轮改用真实建筑装配视角，要求每项最终回答：

- 是什么构件；
- 有多少件；
- 每件在哪里；
- 属于哪种样式；
- 朝向如何；
- 由谁承托；
- 承托或连接谁；
- 尺寸从哪里来；
- 长度如何确定；
- 当前是否已有可用3D模型。

本轮不要求恢复“963年每根原木”的绝对历史状态。目标是建立一个依据测绘资料、结构可信、可参数化装配的万佛殿3D模型。

## 2. 关键方法修正

### 2.1 工程对象与真实构件分离

现有以下工程对象不能继续被当成最终真实构件目录：

- PRIMARY_FRAME
- FRAME_SUPPORT
- BRACKET_ARM
- BRACKET_CONTACT
- ROOF_ENVELOPE
- GRID_CONTROL / FRAME_CONTROL 等控制对象

这些对象仍可作为旧工程基线或控制层保留，但最终实体模型应尽可能回到报告已经明确区分的真实构件。

### 2.2 构件长度不必全部写死

对于长梁、槫、斜撑等构件，允许采用：

> 实测截面 + 明确起止装配节点 = 模型自动求长度

因此“报告没有给单根完整历史全长”不再自动等于“不能建模”。

### 2.3 未确认内容不得猜

凡报告尚未直接确认的总数、逐件位置、45°转角细节、隐蔽榫卯、翼角逐椽等，统一保持“待确认 / 代理 / 合理补全”，不得从一般古建常识直接升级为本项目事实。

## 5. 当前仍未闭合的实例问题

### 5.1 需要从“组”展开到“逐件”

优先继续拆解：

- 丁栿8根的逐根编号、位置与连接；
- 乳栿8根；
- 剳牵14根；
- 托脚12根；
- 叉手8根；
- 正身与两山33根槫的逐根实例；
- 替木总数与各位置；
- 襻间总数与各位置。

### 5.2 斗栱内部仍未形成完整逐件总账

已确认真实构件族，但尚需按每一组柱头铺作、补间铺作逐层展开：

- 每组包含哪些斗、栱、昂；
- 每件朝向；
- 第几跳；
- 与上下哪一件相交；
- 每种变体总数。

不得用旧 BRACKET_ARM / BRACKET_CONTACT 的工程数量直接代替真实构件实例总数。

### 5.3 椽系仍未闭合

当前可以确定槫位、屋面坡向和主要起止关系，但仍缺：

- 椽截面；
- 椽间距；
- 逐根数量；
- 檐部与翼角椽分型；
- 屋面木基层细节。

旧工程层“36 RAFTER proxies”不得解释为真实椽数量。

### 5.4 第四大系统尚未纳入

整殿最终构件清单还缺：

- 台基 / 台明 / 阶条 / 角石等；
- 室内地面；
- 墙体 / 砌体围护；
- 门窗 / 槛墙 / 固定装修；
- 神台等固定建筑设施（如纳入室内模型）。

因此 V001 不能称为“整殿最终完整清单”。

## 6. 对现有 P3 / T-018 的影响

### 6.1 保留的事实

- P3.0 / P3.1 / P3.2 既有验收结论不因本轮自动撤销；
- 现有 11/40/365 继续作为工程基线与历史资产保留；
- 已批准的6类 Master 继续有效；
- T-020 的共享屋脊 X/Y 基准不因本轮自动失效；
- RZ / FV 仍保持已锁定设计状态，不升级为生产真值。

### 6.2 新的边界

> 11类 / 365个工程对象不得再被解释为“万佛殿真实构件完整性已闭合”。

T-018 当前继续 HOLD。  
在真实构件实例总表和关键 Master 缺口进一步闭合前，不恢复：

- RZ/FV生产发布；
- CP-03；
- PR #6 patch；

- Blender整殿生成；

## 7. 当前下一步

优先顺序：

1. 继续把主体木构中的“实例组”拆成逐件记录；
2. 逐组拆解柱头铺作 / 补间铺作内部真实斗栱构件；
3. 闭合替木、襻间、椽系；
4. 复核第四大系统：台基 + 地面 + 墙体 + 围护 / 门窗；
5. 形成真正的《万佛殿整殿构件实例总表》完整版本；
6. 再据此重新判断 Master 补建顺序与 T-018 后续结构。

## 8. 本轮落档结论

本轮最大的事实修正不是“增加了几个尺寸”，而是重新定义了整殿生成的对象：

> **目标应从“生成旧的365个工程对象”，转向“用真实构件库 + 明确实例位置 + 装配关系生成万佛殿”。**

这属于整殿生产前的构件级完整性校准，不是推翻此前所有成果，也不是恢复963年逐木考古复原。
