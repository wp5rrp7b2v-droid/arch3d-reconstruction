## 1. Gate 目标

P3.2 的目标不是完成整座万佛殿建模，而是建立一套**明确、可计算、可验证、可追溯、可重复生成的构件组合关系体系**。

完成后必须证明：P3.1 已批准的独立构件 Master 可以按照明确规则形成代表性组合单元，并为 P3.3 整殿重建提供稳定基础。

## 2. Definition of Done｜9/9 required

| DoD | 验收项 | PASS 标准 |
|---|---|---|
| DoD-01 | 组合范围与构件资格 | 明确哪些 P3.1 正式构件、Proxy、Control、Envelope、Deferred 对象可以进入组合关系模型；所有对象保持原有身份与证据等级，不因进入组合阶段而改变性质。 |
| DoD-02 | 构件关系分类体系 | 建立最小且明确的关系分类，至少覆盖承托、连接、定位、重复、从属。每种关系必须有清晰定义和机器可读表达，不依赖人工目测理解。 |
| DoD-03 | 构件接口与定位规则 | 所有参与正式组合的构件必须具备明确、可计算的接口与定位规则，包括必要的参考点、参考面、方向和变换关系。不得依赖人工手摆位置作为正式关系；具体实现方式不在 DoD 中锁死。 |
| DoD-04 | 代表性组合单元与关系覆盖 | 建立一组最小但有代表性的组合单元，至少覆盖：①竖向承托链；②横向/梁架组合链；③至少一种重复关系。组合单元必须引用正式 Registry 中的构件身份，不得复制后失去身份。 |
| DoD-05 | 尺寸与参数传递 | 建立建筑层级尺寸与构件参考尺寸之间的明确边界。构件在组合中的实际尺寸、位置和重复关系必须由正式组合参数驱动；不得将非历史 reference specimen 尺寸直接继承为建筑实际尺寸。 |
| DoD-06 | 史料依据与不确定性边界 | 关键构件关系必须能够追溯其依据等级。已知、合理补全、工程控制、UNKNOWN 等状态必须保持显式；模型能够组合，不等于历史关系已被证明。 |
| DoD-07 | 机器验证与组合关系完整性 | 建立自动验证，至少检查缺失节点、非法关系、孤立节点、重复身份、非法自连接、非预期循环、父子关系矛盾、Registry 不存在节点、关系端点类型错误、reference length leakage 等。Hard Fail 必须能够阻止 Gate PASS。 |
| DoD-08 | 确定性重建与参数变更验证 | 能够从 Registry + 组合规则 + 参数确定性重建测试组合单元；通过独立重开验证；至少执行一次参数变更 → 重建 → 验证 → 恢复标准状态，证明结果不是一次性人工摆放。 |
| DoD-09 | P3.3 整殿重建就绪性验证 | 必须证明 P3.3 可以基于正式构件库、构件组合关系和建筑层级参数开始整殿重建，而不需要重新发明基础关系体系。所需 Schema、Registry、验证结果、审核图和必要说明必须齐全，并经 Product Owner 审核。 |

## 3. Hard Fail

### HF-01｜参考长度泄漏到实际组合

六椽栿 `canonical_reference_length_mm=1000` 仅为非历史标准参考长度。若该值被直接用于万佛殿实际组合尺寸，立即 FAIL。

### HF-02｜对象被静默历史化

Proxy、Control、Envelope、Deferred、UNKNOWN 等对象不得因为进入组合模型而自动变成历史正式构件或历史确定关系。发生即 FAIL。

### HF-03｜人工摆放被伪装成组合系统

如果组合结果只能依赖 Blender 中现成位置存在，而不能由**正式构件身份 + 构件组合关系 + 参数**重新生成，则 FAIL。

## 4. P3.2 Non-goals

P3.2 不要求：

- 完成整座万佛殿；
- 完成全部榫卯细节；
- 进行结构力学计算；
- 证明所有组合关系均为北宋原始做法；
- 补完全部 Deferred 构件；
- 完成高精度材质、纹理与最终渲染；
- 对 P2 的 365 个既有实例逐件人工建立关系；
- 因视觉组合完整而提高历史可信度。

## 5. P3.2 / P3.3 边界

- P3.1：解决“构件是什么”。
- P3.2：解决“构件怎样组合”。
- P3.3：解决“如何用这些构件和规则重新组成整座万佛殿”。

P3.2 PASS 的核心判断是：**进入 P3.3 后，不再需要重新发明基础的构件组合机制。**
